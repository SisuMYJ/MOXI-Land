# 墨西岛功能完善验收标准

本清单用于把 Prototype v1 推进到可稳定试玩、可继续扩展内容的功能基线。视觉重设计不在本轮范围内；居民总库、居民对话和居民小故事由独立内容库提供，本轮只保证接入接口与空数据兼容。

## A. 每日状态与地图同步

- [x] 商店商品、Lumo 台词、天气和外出居民使用同一份 `daily` 状态。
- [x] 应用启动、跨本地午夜、窗口重新聚焦和页面恢复可见时刷新每日状态。
- [x] 天气、外出居民或扩岛状态变化后，Phaser 地图同步更新。
- [x] 地图渲染不依赖挂载在 `window` 上的全局游戏状态。

## B. 经济与成长闭环

- [x] 商店只接受商品 ID，并在 Store 内校验当日上架、价格和货币。
- [x] 礼物保留内容标签；无效居民、非礼物物品和零库存不能被送出。
- [x] 玩家拥有独立背包入口，可查看礼物、碎片、资源和奖励。
- [x] 农场有明确容量；容量已满时不能继续购买农场物品。
- [x] 解锁“新农场”会提升农场容量，形成可感知的扩岛收益。
- [x] 成熟产物出售提示使用玩家可读名称，而非内部资源 ID。
- [x] 中断探索可以重新整备开始，不会形成永久死档。

## C. 存档与日期可靠性

- [x] 存档包含 schema 版本，并能迁移无版本的旧存档。
- [x] 损坏或类型不合法的存档安全回退，不阻止游戏启动。
- [x] 存储写入失败不会让玩家操作崩溃。
- [x] 每日限制统一使用玩家本地日期。

## D. 工程质量

- [x] 提供无需新增第三方测试依赖即可运行的自动化测试命令。
- [x] 每日抽取、存档容错及核心商店/送礼行为有回归测试。
- [x] 提供独立 `typecheck`、`test` 和 `check` 命令。
- [x] 生产构建通过，Git diff 无空白错误。

## E. Web 发布基础与可访问性

- [x] HTML 包含语言、viewport、标题、描述和主题色等基础元信息。
- [x] 弹窗具备 dialog 语义、Escape 关闭、初始聚焦和关闭后焦点恢复。
- [x] Toast 可被辅助技术感知，表单控件具有可读标签。
- [x] 键盘焦点有清晰可见状态。
- [x] Phaser 游戏代码从 React 首屏入口拆出并异步加载。

## 内容边界

- 不在本轮新增或改写居民角色、居民对话及居民故事。
- 运行层只消费 `Resident[]` 和每日居民 ID；未来居民总库可在内容层或远端适配层替换。
- 居民池为空、当日无外出居民时，地图仍应正常渲染。
